# 工作台 S3：文件快照与安全恢复

S3 为 S1 会话树和 S2 本地聊天服务增加项目基线、文件快照、本地修改检查点、
恢复预览和显式中断恢复。项目问答、修复执行与编辑后的重新执行已由
[S4](WORKBENCH_S4.md) 接入；本地会话树和预览界面见 [S5](WORKBENCH_S5.md)。

## 交互语义

查看历史仅移动浏览位置，文件与执行分支保持当前状态。实际恢复必须先生成预览，
再提交该预览的 ID。预览展示每个路径的旧、新类型、大小、权限和 SHA-256，
不返回文件正文；客户端应将删除、创建、修改和类型变化明确展示给用户。

假设原分支依次执行 1、2、3，其中 3 修改代码，之后用户又手动修改文件：

1. `input` 预览选择第 1 轮的输入快照，恢复到它执行前的文件状态。
2. 应用前保存当前完整状态；成功时将手动修改作为“本地修改”检查点追加到原分支。
3. 新分支从第 1 轮的父节点出发，追加“恢复检查点”，原分支的 1、2、3 均保留。
4. 新分支不会继承 2、3 的模型上下文，也不会自动重放它们。S4 在该状态执行编辑后的请求。
5. 切回原分支头，可恢复第 3 轮输出及保存的手动修改。

`fork` 表示从某节点**执行后**继续，`input` 表示从某轮**执行前**继续。
`fork` 的 `node_id: null` 恢复会话初始基线。失败或取消运行若保存了输出快照，
该部分改动同样是有效的节点文件状态。快照未保存的文件差异视为本地修改。

切换分支会保留分支名并追加恢复检查点。如果目标是当前分支，且存在手动修改，
则为目标状态创建新分支，使当前分支仍指向保存了手动修改的检查点。

## 文件范围

快照包含管理范围内全部普通文件（包括二进制和未跟踪文件）、目录及权限。
Windows 权限只记录文件只读属性，目录权限归一为 0755；Linux 记录 POSIX 权限位。
不运行 `git reset`、`checkout` 或 `clean`，Git HEAD、索引和提交历史不变。

策略版本固定为 `workbench-files-v1`，每层目录均排除以下名称（大小写不敏感）：

- `.git`、`.fixloop`、`.agent`、`.agents`、`.codex`、`.claude`、`.cursor`。
- `.aws`、`.ssh`、`.gh-config` 和以 `.env` 开头的名称。
- `.venv`、`venv`、`node_modules`、`__pycache__`、`.pytest_cache`、`.ruff_cache`、
  `.mypy_cache`、`dist`、`build`。
- `.fixloop-s0-private-` 前缀的内部事务文件。

这是固定文件范围，不读取 `.gitignore`。管理范围内发现符号链接、junction、
reparse point、硬链接、特殊文件、路径歧义或大小写别名时拒绝快照。
含排除项的目录不能被恢复操作删除或改为文件，避免连带移除受保护数据。
项目根和祖先不能使用链接别名，项目目录与状态、锁目录必须互不包含。

上限为单文件 32 MiB、全树 128 MiB、20,000 个条目。超过上限会拒绝操作，
不会静默遗漏文件。快照完成后再次扫描，发现变化则要求重试。

## 存储与所有权

默认状态目录为 `~/.fixloop/workbench`，在 S2 文件之外增加：

- `snapshots/blobs/<sha256>`：不可变文件内容。
- `snapshots/trees/tree-<sha256>`：规范化 JSON 文件清单，包含根目录身份和策略。
- `restores.sqlite3`：恢复事务及每个文件操作的进度，持久化后才开始写文件。

预览保存外部快照但不改变项目或会话树。最多同时保留 32 个预览，10 分钟失效，
重启后需重新预览。每次应用重新核对会话 revision、根目录身份、实时全树和快照摘要。
状态数据必须由本地可信用户管理；不支持其他程序直接修改内部数据库、清单、锁和事务文件。
快照内容含项目数据，固定排除策略不能识别任意位置的凭据。当前没有快照垃圾回收或加密。

每个项目使用默认共享锁目录 `~/.fixloop/project-locks`，独立于服务状态目录。
服务打开已注册项目时重新持有 OS 锁；服务退出或崩溃自动释放。
同根和嵌套根不能被不同服务同时管理。测试可注入共享临时锁目录，生产服务须沿用默认目录。
MVP 一个项目只关联一个会话，同一会话内可有多个分支。尚未提供跨会话共享项目的状态切换。

## 中断与外部编辑

恢复不是跨文件原子操作。写入时对每个原始文件重新验证，保留备份，
通过拒绝覆盖现存新文件的重命名发布目标内容。Windows 使用原生句柄固定根和祖先，
拒绝链接，写 staging 时使用 delete-pending 阻止创建硬链接别名。
Linux 使用 dirfd、`O_NOFOLLOW`、`renameat2(RENAME_NOREPLACE)` 和匿名 `O_TMPFILE`。
Linux 文件系统必须提供这些能力以及 `/proc/self/fd`，不支持降级为普通覆盖写入。
目录权限不受进程 umask 影响；必要时暂时增加所有者权限以恢复子项，最后恢复目标权限。
这些中间权限变化同样记录在事务步骤中，供中断恢复使用。

外部编辑器仍可并发写文件。发现未知改动时停止并保留已保存的快照与备份，
不承诺把整个工作区锁成跨文件原子状态。事务期间尽量暂停外部写入。
进程崩溃后，项目会进入待恢复状态；重启不自动写回项目，不自动继续执行模型。

客户端通过 `workspace` 获取原事务 ID，明确选择：

- `complete`：完成目标文件恢复并提交会话树。
- `rollback`：恢复应用前文件状态，保留原会话树。

恢复前也核对已记录的中间状态，新的未知编辑会阻止覆盖。恢复自身再次中断时，
继续原事务 ID 和已经选择的决定即可。需要人工保留或移走冲突文件、让工作区返回日志可识别
的状态后再重试；不存在强制覆盖接口。内部备份不要手动删除。

SQLite 历史提交包含源分支手动修改、新分支或分支选择、目标检查点，在一个事务内完成。
目标快照带不可变事务收据，用于辨认“历史已提交、外部日志尚未结束”的崩溃窗口。
这种情况下只能 `complete` 清理并结束事务；若要返回旧状态，结束后另做预览恢复。

## API

启动和认证沿用 [S2](WORKBENCH_S2.md)。以下 `C=/api/conversations/{conversation_id}`。

| 方法与路径 | 请求 | 结果 |
| --- | --- | --- |
| `POST /api/conversations` | `{title?, project_path}` | 201，会话和初始基线原子登记 |
| `GET C/workspace` | 无 | 本地差异、策略和未完成事务 |
| `POST C/checkpoints` | `{label?, expected_revision?}` | 201，本地快照检查点 |
| `POST C/restores/preview` | `{action, node_id?, branch_id?, name?, expected_revision?}` | 201，预览 ID 和变更列表 |
| `POST C/restores/apply` | `{plan_id}` | 200，已提交事务 |
| `POST C/restores/recover` | `{operation_id, decision}` | 200，已恢复事务 |

`action` 为 `switch`（必须提供 `branch_id`）、`fork`（节点可为空）、
`input`（必须为普通轮次节点）；`decision` 为 `complete` 或 `rollback`。
预览绑定目标会话和 revision，应用不接受客户端传入文件清单。
项目会话的旧 `/fork`、`/switch` 接口返回 422，要求使用预览和应用接口。
项目发送、编辑和重新生成已由 S4 接入，参数和执行语义见 [S4](WORKBENCH_S4.md)。

陈旧预览、忙碌会话、未完成事务或新文件冲突返回 409；不存在的对象返回 404；
非法参数或损坏清单返回 400。原生磁盘操作失败可能返回 500，此时读取 `workspace`
检查事务状态，不能将请求失败视为“没有文件变化”。

## 验证

`tests/test_workbench_restore.py` 覆盖真实项目文件、二进制、未跟踪文件、目录和类型变化、
权限、链接与路径安全、快照损坏、陈旧预览、外部编辑竞态、历史事务原子性、
跨状态目录项目锁、原始未来保留、故障恢复、恢复再中断及独立进程崩溃。
HTTP 验证使用真实 loopback 服务，模型执行使用本地 fake。S3 的历史轮次测试模拟
S4 写入输出快照，未接入真实修复模型，也未运行仓库全量测试。

本次相关验证累计通过 Windows S3 用例 50 个、S1/S2 回归用例 82 个，
并通过 Ruff 检查与格式检查。失败修复后仅复验失败或直接受影响的用例。

`tests/native_workbench_smoke.py` 在 WSL Ubuntu 上实跑 10 个 Linux 原生用例，
覆盖二进制、目录与文件类型切换、权限及 umask、只读目录内容恢复、手动修改分支、
陈旧预览、链接与特殊文件、根替换、发布竞态、显式恢复与独立进程崩溃。
该标准库测试仅跳过 `agent_runtime` 的模型依赖入口；实际文件与恢复模块没有替换，
测试项目位于 Linux `/tmp`。没有在 Linux 环境运行完整服务或 HTTP 回归。
