# 证据消费 MVP：校验解释、必需摘要与请求记录

日期：2026-10-02。范围：用户确认的证据消费增量，承接 [代码探索消费链](CODE_EXPLORATION_CONSUMPTION_ACCEPTANCE_2026-10-01.md)、[长任务状态](LONG_TASK_CONTEXT_ACCEPTANCE_2026-10-01.md) 和 [上下文组装](CONTEXT_ASSEMBLY_ACCEPTANCE_2026-10-02.md)。复用 EvidenceLedger、Observation、PlanSession、最终 context manifest 与 checkpoint，不新增数据库、自动检索、自动重规划或摘要模型。

## 实现与消费路径

1. **解释现有谓词。** `EvidenceLedger.inspect()` 返回证据类型、`valid/stale/invalid/unknown`、原因、`current/historical` 用途、完整记录 checksum 和依赖检查树。`valid()` 继续返回布尔值，完成条件仍由原有谓词与回执决定。缺失、篡改、身份冲突、依赖循环、坏回执明确拒绝；版本变化标 stale，版本缺失或工作区不可核验标 unknown，不提升为成功。
2. **当前节点必需摘要。** `build_required_context()` 校验当前节点必需证据后，从持久记录直接投影事实摘要，进入受压缩保护的 state。正文仍是可选内容；历史、记忆或源码片段为空时，模型仍得到当前分析结论、检索边界或执行回执说明。投影失败明确阻断，不静默省略；超预算仍不调用模型。
3. **最终消费记录。** 编码及最终裁剪后生成 `evidence_consumption`，区分校验状态、`summary_in_request`、`body_in_request`、正文形式和未入选原因。以 `(evidence_ref, use)` 区分同一证据的当前与历史用途。checkpoint 深拷贝这些字段，恢复仍从 owner/journal 和当前 Plan 重建。

```text
当前节点所需引用 → 完整校验与依赖原因
                  → 持久事实摘要 → 必需预算
Observation 正文 → 既有 freshness/scope/blob 检查 → 可选预算
                  → 最终编码/裁剪 → 消费 manifest → 发送前复验
```

native 显式工具尾部的引用也进入正文检查候选，不依赖它是否已出现于会话历史。工具配对和完整组舍弃继续沿用上下文组装契约。

## 四类事实摘要

| 证据类型 | 保留说明 | 能证明的范围 |
|---|---|---|
| `observation_present` | Observation 引用、工具、参数预览、检索执行/完整性/范围/截断原因 | 已记录的工具结果；不证明搜索穷尽，正文是否可作为当前源码另行检查 |
| `analysis_recorded` | 结论预览、输入引用、语义正确性未认证的说明 | 已记录分析及其输入依赖，不证明结论正确 |
| `patch_applied` | 修改路径、receipt/call/run 身份、成功与停止事实 | 对记录版本确认的修改，不授予重放权限 |
| `tests_passed` | 命令预览、run/attempt 身份、完成/通过/测试数 | 对记录版本完成的验证，不证明测试覆盖全部需求 |

摘要包含证据 ID、校验状态和用途。字段预览默认最多 512 字符；超过时标明 `omitted_fields`，不改写完整持久记录。对象/列表过长时变为明确的 JSON 文本预览，不能当作完整结构使用；上限是逐字段限制，全部摘要仍须通过总预算门禁。

完整文件版本映射及记录 checksum 保留在 ledger 和检查/消费记录中。模型摘要采用明确命名的 `record_checksum_prefix`（12 字符）作显示标识，整仓范围使用 `whole_workspace`，局部来源结合参数和检索范围说明。短标识不用于完整性校验，不替代完整 checksum；所有校验、回调复验和恢复均使用完整记录。省去重复的版本哈希与范围说明，保留有限预算下的事实和引用。

## 语义与取舍

- **记录有效不等于正文新鲜。** Ledger 的现有版本谓词与源码消费的有界 SourceChecks 各自检查自己的契约。`valid` 不能自动推导正文已入选、范围完整或模型已阅读。
- **确认后态保持历史输入。** 补丁记录的历史依赖只检查归档完整性和身份，不要求旧输入仍匹配当前源码；当前补丁/验证记录继续检查记录版本。不能为了刷新旧证据再次执行已经确认的写入。
- **记录请求准备结果。** `summary_in_request/body_in_request` 表示最终准备的请求包含相应内容，不是 provider 接收确认，更不是模型理解证明。正文形式明确为源码片段、工具反馈、native 结果或历史摘录；片段/摘录入选不代表整个原始 blob 已发送。
- **范围保持小。** 只追踪当前节点必需证据及其依赖，不追踪所有记忆、知识项或任意历史文本。未经过正文校验的引用不计为已确认正文消费。没有新增决策版本、置信评分、通用证据图、自动提炼或全入口迁移。
- **成本仍有边界。** 摘要增加必需 token；超长请求仍可能阻断。Ledger 继续使用既有工作区快照，正文校验继续有界 I/O，不保证原子文件系统快照，也没有新增性能承诺。

借鉴 [五维参照](AGENT_DESIGN_REFERENCES_2026-10-01.md) 中 Pi 的语义投影/provider 编码边界（R-02）和 OpenCode/Pi 的输出裁剪、摘要与预留职责区分（R-03）。四类摘要、状态解释和消费字段是 FixLoop 对现有契约的本地实现，不宣称上游提供相同格式。Hermes 的历史检索/经验候选（R-08/R-09）继续后置。
